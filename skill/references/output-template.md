# 输出模板

三类输出的骨架。照抄结构，内容按事实库填。

## 通用格式

开头一行徽标，说明分类和理由：

```
【A 类 · 措辞型】核心要求 5 条，无证据 0 条。能力都已具备，问题在怎么说。改简历有效。
【B 类 · 重构型】核心要求 4 条，无证据 1 条，弱证据 2 条。经历够，但全篇写成了执行者。
【C 类 · 资格型】核心要求 4 条，无证据 2 条（SQL、BI 工具）。这不是措辞问题，改简历救不了。
```

编号写法：`[f-013]`，紧跟在对应结论后面。一句挂一个，不要一句话挂三个。
强度写法：强 / 中 / 弱 / 无，四个字，不加修饰。

---

## A 类模板

```markdown
【A 类 · 措辞型】<理由>

## 一、这个岗位要什么
1. R1 <一句人话>
2. R2 <一句人话>
...

## 二、你手里有什么
| 要求 | 强度 | 依据 |
|---|---|---|
| R1 | 强 | <做了什么，带数字> [f-006] |
| R2 | 弱 | <技能栏写了，但项目里没有对应动作> [f-009] |
...

## 三、缺什么
能力缺口：<几条，逐条点名；没有就明说 0 条>
更麻烦的：<不是能力的那一件事。通常是可信度、外部使用者、可验证性>

## 四、哪几句该怎么改
### ① <位置>
原句：> <逐字引用>
建议：> <改写，只能重组已有信息>
理由：<为什么这么改> [f-013] [f-016]

### ② ...
（最多 3 句。改 10 句等于没改）
```

第四段的硬约束：
- 一次最多 3 句
- 必须逐字引用原句
- 理由里必须说清「原来那版的问题是什么」，不能只说「这样更好」
- 改写只能用事实库里已有的信息重组

## B 类模板

不输出四段。先输出追问，等回答。

```markdown
【B 类 · 重构型】<理由>

## 先说结论
你的经历够，但简历把你写成了配角。全篇 12 个动作动词里有 7 个是「配合 / 参与 / 协助」。

## 我需要你先回答三个问题

1. <针对最弱的那一条>那段时间里，有没有哪一件具体的事是你自己拿的主意？
2. 当时还有别的做法吗，为什么没选它？
3. 这件事最后的结果，有没有数字或者别人的评价？

回完这三个，我再帮你重构。**在此之前我不会动你的措辞**——因为在你的原话里，
这些事都还是「配合」的，我不给你升级成「主导」，面试第一问就会露。
```

拿到回答后，把回答作为新事实入库（编号往后接），再按 A 类四段输出。

## C 类模板

```markdown
【C 类 · 资格型】<理由>

## 一、现在不建议投这个岗

JD 第一条硬要求是 <X>，你没有 [f-0xx]。第二条是 <Y>，你也没有。
这不是简历写法的问题，是能力项缺失。改措辞只能让你在初筛被挂得更体面一点。

<如果只有一条缺失但恰好是第一条，也归 C：第一条缺失，后面写再好也过不了初筛>

## 二、你真正能带走的东西

| 可迁移能力 | 依据 |
|---|---|
| <通用词，如：一手用户需求来源> | <具体做了什么> [f-010] |
| <通用词> | <...> [f-012] |

（3–4 条。这一栏不能敷衍，因为它是用户现在唯一能用的资产）

## 三、时间账

补齐最短路径：**<N> 个月**
卡点：<最花时间的那个具体技能，不要写「系统学习」>
第一步（本周可做）：<一个能在两天内完成的具体动作>

## 四、现在该投什么

建议方向：<岗位名>
为什么是同一扇门：<用他现有的经历说明这个岗位要的正是他有的>
不要再投：<哪一类，说清原因>
```

C 类三条禁令：
- 不许给逐句改写，一句都不行
- 时间账不许写「尽快」「一段时间」，必须给月数
- 不许只写「你不合适」，必须给「现在该投什么」

## 落盘格式

文件名：`<YYYY-MM-DD>-<岗位简称>.md`

报告末尾固定加一段：

```markdown
---
校验：scripts/verify_citations.py 已通过（引用 N 个编号，0 处未知，0 处动词升级）
分类：<A/B/C>
本轮新增事实：<编号，没有就写 无>
```
