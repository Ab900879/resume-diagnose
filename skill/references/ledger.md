# 事实库

事实库是整个技能的地基。没有它，输出就是模型即兴发挥；有了它，每句话都能被验证。

## 位置

默认 `D:\Opc\resume\ledger.json`。不存在时依次回退到工作目录 `.resume/ledger.json`。
用户显式指定路径时以用户为准。

## 结构

```json
{
  "meta": {
    "owner": "张照泉",
    "updated": "2026-11-02",
    "source": "简历 PDF · 3 页",
    "note": "只记原文有的信息"
  },
  "facts": [
    {
      "id": "f-001",
      "type": "项目",
      "text": "用 ReAct 思路让 Agent 调用 3 个工具，先写 PRD 定下查不到就拒答的规则",
      "verb": "独立完成",
      "time": "2026.05-06",
      "source": "项目 3 · 第 2 段",
      "verifiable": "高",
      "forbidden_rewrite": ["3 个工具", "ReAct", "2026.05-06"],
      "transferable": ["提示词设计", "边界条件定义"]
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `f-001` 起，只增不改。删掉的编号不复用 |
| `type` | 是 | 教育 / 实习 / 项目 / 校园 / 技能 / 个人 |
| `text` | 是 | 用原文说法，一句话。不加形容词 |
| `verb` | 是 | **原样抄原文的动词**：负责 / 参与 / 协助 / 配合 / 主导 / 独立完成 / 执行。这一栏是判断"他到底是不是执行者"的唯一依据 |
| `time` | 是 | 原文写的，没写填 `未标注` |
| `source` | 是 | 指回原文哪一段，供抽查 |
| `verifiable` | 是 | 高 = 有物证（链接、后台数据、上线的东西）；中 = 有人能证明；低 = 只有本人记得 |
| `forbidden_rewrite` | 否 | 这个词条里的数字、技术名词、组织名，输出时不许改 |
| `transferable` | 否 | 能证明的通用能力，用通用词：活动策划 / 数据整理 / 跨部门沟通 |

## 建库步骤（第一次用时）

1. 取简历原文（PDF / 文档 / 用户粘贴），逐段读完
2. 按上面格式拆成条目。**只记原文出现的公司名、数字、时间、技能**
3. 随机抽 5 条回原文逐字对一遍。对不上说明在编，重来
4. 数量门槛：
   - ≥8 条 = 合格
   - 6–7 条 = 合格，但在报告末尾加一句「简历信息偏少，结论会偏保守」
   - ≤5 条 = 不做诊断，直接告诉用户「这份简历信息太少，先补经历再来」
5. 存盘，`meta.updated` 填当天

**门槛为什么是 8 不是 20**：首轮实测里 5 份样本没有一份能拆到 20 条，最多的 9 条。真实学生简历通常 6–10 条。门槛定 20 会让工具对所有人罢工。

## 维护规则

- 编号只增不改，删掉的不复用——报告里的历史引用才不会指错
- 用户补充了新经历，追加入库，`source` 标 `用户口述 2026-11-05`
- B 类追问得到的回答，也入库。这是最值钱的一类事实，因为它是用户自己说出来的判断
- 简历更新后不要重建库，做增量。重建会让旧报告全部失效

## 隐私

事实库含真实姓名、公司、数字，**不进公开仓库**。
对外发布时只发 `references/` 里的规范和 `scripts/`，事实库留在本地。

这不是技术限制，是产品设计：逻辑公开，数据私有。
