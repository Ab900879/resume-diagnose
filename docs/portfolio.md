# 作品集 · 一个 AI 产品从 0 到 1

> 这份文档不是产品说明，是**一次完整的汇报**：如果我要把这个项目从头讲给面试官或团队听，就讲这些。
> 结构按产品方法论排：需求洞察 → 竞品 → PRD → 决策 → 版本 → 评测 → badcase → 指标 → 还差什么。
> 每一节的依据都指向仓库里的真实文件，没有一处是事后补的。

---

## 一、一句话定位

**先说这个岗该不该投，再决定改不改的简历诊断工具。**
输入一份简历（可选一份 JD），输出：HR 视角的匹配判断 + 一份可直接投递的改好简历 + 一份继续攒经历的路径。

不打分、不美化、不编造经历。它唯一比通用大模型强的地方是：**会告诉你哪句话没有证据，应该删掉。**

## 二、需求洞察

| 项 | 内容 | 依据 |
|---|---|---|
| 用户 | 投了十几家没回音、改过两版简历、说不清自己哪段经历算不算数的人 | 第一个用户是作者本人（2027 届，投 AI 产品实习） |
| 问题 | 不是"简历不好看"，是"我这段经历到底算不算数" | 案例-01 自测记录 |
| 现有方案 | 通用大模型改简历；招聘平台自带的简历诊断 | 竞品拆解见下节 |
| 差别 | 别的工具给 10 条润色建议，这个会说「这条你没有证据，删掉」 | PRD §2.2 |
| 成功定义 | 他照着改了、投出去了，或者主动删了一句原本以为加分的句子 | PRD 三处待验证 |
| **未验证** | **只有 1 个真实用户（作者自己）** | 见第九节 P0-1 |

**一个被数据推翻的假设**：最初想做的是"简历优化助手"。5 份样本测完发现，其中 4 份不该给改写建议——经历根本不匹配。
产品流程因此倒过来：先分类（A 措辞型 / B 重构型 / C 资格型），C 类不给任何逐句改写。

## 三、竞品拆解

| 对手 | 它怎么做 | 它的优势 | 我不学什么 | 我要的差别 |
|---|---|---|---|---|
| 通用大模型（ChatGPT / 豆包） | 贴简历 + 说"帮我优化" | 零门槛、表达好 | **学它的润色** | 它会把「协助」写成「主导」。我不做——事实库编号 + 校验器，动词升级会被抓出来 |
| 招聘平台简历诊断 | 关键词匹配打分 | 有岗位数据 | **不学打分** | 分数没法指导行动。我给"哪条没有证据" |
| 简历代写服务 | 人工包装 | 结果好看 | **不学包装** | 包装出来的句子面试一问就露 |
| 同类创作者（抖音，20 个大厂 JD 整理） | 拆 JD 做内容，引流到自己的工作流 | 内容获客能力强 | **借鉴它的洞察** | 他验证了"AI 岗位分四个方向"——已吸收进类需求库第〇节 |

## 四、PRD 摘要

完整版：[`docs/PRD.md`](PRD.md)（331 行）

**功能边界（写死的"不做"）**：不生成整份简历、不打分、不美化措辞、不替没经历的人包装、不爬招聘平台 JD。

**判定方式**：每条 JD 要求评强度（强/中/弱/无）→ 按无和弱的数量分 A/B/C。

**通过线**：
- 输出每句话必须挂事实编号，挂不上就删（`verify_citations.py` 强制执行）
- A/B 类必须有 rewrites 或 gaps；C 类必须有 gaps 或 transferable（不满足自动换模型重跑）
- 简历正文零说明文字（纯净度检查）

**反指标（做错了长什么样）**：
- 输出里出现"闭环/赋能/沉淀"等黑话 → 失败
- 改动清单里出现原句新句一字未变的"假改动" → 失败
- 技能栏保留没有项目支撑的技能 → 失败

## 五、三个被我否掉的方案

| 方案 | 为什么否掉 |
|---|---|
| 爬招聘平台 JD 建需求库 | 能做，但不该做。《个人信息保护法》+ 平台协议。"能不能做"和"该不该做"是两个问题 |
| 在提示词里写"禁止编造" | 那是请求，不是强制。模型可以不听，而且我无法验证它听没听。改成事实编号 + 可执行校验器 |
| 三天做一个网页上线 | 空洞不是缺代码，是没人用过。先做人力版（人力跑完 7 天流程）再谈自动化 |

## 七、评测

两次真实评测，数据都在仓库里：

| 评测 | 规模 | 结论 | 文档 |
|---|---|---|---|
| 提示词实测 | 5 份样本 | 召回 5/5，4 个硬伤（全部修复） | [`eval-report-v1.md`](eval-report-v1.md) |
| 模型选型实测 | 33 个模型 × 同一输入 | `auto` 首字 206 秒 → `glm-5.3-flash` 1.5 秒；发现 1 个静默空报告 | [`模型实测-2026-11-02.md`](模型实测-2026-11-02.md) |
| 真实简历三轮 | 作者本人简历 ×3 | A 类、校验 PASS、纯净度 PASS、删掉 2-5 项无证据内容 | 见各次产出 |

**一条被自己推翻的判断**：我原本按模型元数据（"强制思考 = 肯定慢"）筛掉慢模型，结果把最快的筛掉了、留下了会输出空报告的。
**结论：模型快慢只能实测，不能靠字段推断。** 这条已写进代码注释。

## 八、Badcase 归因

完整档案：[`badcase-log.md`](badcase-log.md)（BC-01 ~ BC-09，P0/P1/P2 分级）

摘要三条最有代表性的：

- **BC-01 静默空报告（P0）**：模型给了分类和理由，但所有内容段落是空的，页面却显示"诊断完成"。
  归因：只校验"有没有 class 字段"，没校验"这个分类该有的内容有没有"。**格式合规 ≠ 内容有效。**
- **BC-02 五分钟无响应（P0）**：默认取模型清单第一条，而它是推理模型（首字 206 秒）。用户跳走页面，任务丢失。
- **BC-07 对单份 JD 定制化（P2）**：产品假设错了。用户真实用法是拿一份简历投一类岗位。这一条**不是测出来的，是用户说出来才知道的**。

规律：**P0 全是静默失败；P1 全是提示词没堵的口子；P2 只能靠真实用户发现。**

## 九、这个项目要真正落地，还差什么

> 这一节是我以产品经理的视角对自己项目的自查。**故意写短板，因为敢写短板的人，写的强项才可信。**

### P0 级（不做完，它只是个玩具）

| # | 缺什么 | 具体表现 | 我的判断 |
|---|---|---|---|
| P0-1 | **没有真实用户** | 只有作者 1 人，而且我知道预期答案，无法证明"它能给出人没想到的判断" | 唯一不能靠 AI 或工具补的一项。已定验证动作：找 3 个正在投简历的人，问"哪一句是你原本没想到的" |
| P0-2 | **没有反馈回路** | 用户投出去之后发生什么，产品一无所知。北极星指标无法测量 | 最该补的一项。修法：加"投后回报"入口（3 个字段：投了几家 / 有没有面试 / 面试问了什么），把工具变成系统 |
| P0-3 | **分类判据不稳定** | 同一份输入连跑两次，一次 B（改改能投）一次 C（先别投）——两个结论对人是相反的行动指令 | 判据目前是描述性语言，靠模型体会。已往"数编号"的硬条件上挪（类需求库 H/P/D 编号），但未完成。当前页面明示"分类仅供参考" |

### P1 级（影响能不能规模化）

| # | 缺什么 | 说明 |
|---|---|---|
| P1-1 | 无埋点 | 不知道用户卡在第几步、报告哪段被读。没有数据就没有迭代依据 |
| P1-2 | 无账号体系 | 事实库存在浏览器本地，换设备要重建；免 Key 的限额靠本地计数，清缓存就能绕过——不是真熔断 |
| P1-3 | 成本无全局熔断 | 免 Key 走作者额度，只有"每设备每天 20 次"的软限制，遇到脚本刷会瞬间耗尽 |
| P1-4 | 模型单点依赖 | 现在靠实测选的 `glm-5.3-flash`，但它下架或变慢，没有监控也没有告警 |
| P1-5 | C 类输出偏薄 | 说了"先别投"，但没形成"三个月怎么变 B 类"的可复用模板 |
| P1-6 | 合规优势没被展示 | "简历不上传服务器"是最大卖点，但页面上没讲清楚。卖点不被看见等于没有 |

### 指标（现在全是 0，因为没有采集）

- **北极星**：照着改并投出去的人数
- 过程指标：报告完读率 / 改动采纳数 / 二次回来率 / 投后回报率
- 现状：**全部无法测量** —— 这本身是 P0-2 的一部分

## 十、AI 分工线

> 面试被问"哪些是 AI 做的"，答这一节。

**交给 AI**：页面代码、JS 模块、docx 解析的算法实现、文档排版、提示词初稿。
**我自己做的**：

1. 定义"什么叫做对了"（北极星指标 + 反指标）
2. 否掉三个更省事的方案（爬虫 / 提示词防编造 / 三天上线）
3. 决定第一步是"分类"而不是"改写"
4. 把三分类判据写成可判定条件（进行中）
5. 承担代价：C 类拒绝给改写会流失用户；事实库要求人工建，做不成一键上传

一句话：**错了要有人负责的，我自己来；错了可以重来的，交给 AI。**

## 十一、现在就能做的下一步

**找一个人跑一遍，问他一句：「哪一句是你原本没想到的？」**

- 他说得出来 → P1 假设成立，产品在提供认知增量
- 他说不出来 → 这工具只是把他的话换个说法，产品要重做
- 他直接关掉 → 第一屏有问题，更要知道

三种结果都有价值。这是目前唯一能同时补上 P0-1 和 P0-2 的动作。
