## 一、这东西现在能干什么

给一份简历（文字 / docx / pdf / 图片）+ 一个岗位方向，它出五份东西：

| 产出 | 一句话 |
|---|---|
| 诊断 | 你现在该不该投这类岗（A 措辞型 / B 重构型 / C 资格型），按 HR 看前 3 屏的标准判 |
| 改好的简历 | 干净到能直接投，联系方式和技能栏都过筛 |
| 改动说明 | 每一处为什么改、出处在哪 |
| 事实库 | 带编号的经历条目，下次改简历直接复用，不重拆 |
| 成长路径 | 往这个方向继续走该做什么，本周就能启动的那一件 |

**它不做什么**（写死的边界，不是没做完）：

- 不打分。分数会让人以为改到 85 分就能投。
- 不美化措辞。能力不够的人，改得漂亮只是挂得更体面。
- 不生成没有依据的经历。挂不上事实编号的句子一律删。
- 不预测能不能收到面试。它只判人岗匹配。

## 三、已知缺陷：不修了，以及为什么不修

这一节是封版的核心。以下问题**不是忘了**，是判断后决定留到下一版。

| 编号 | 问题 | 影响 | 为什么不现在修 |
|---|---|---|---|
| P0-1 | 没有真实用户，只有作者自己 | 证明不了"它能给出人没想到的判断"——作者知道预期答案 | 修它不需要写代码，需要去找人。**这是唯一的真缺口** |
| P0-2 | 没有反馈回路 | 用户投出去之后发生什么，产品完全不知道；北极星指标（照着改并投出去的人数）当前一个都测不出来 | 要先有真实用户，才有得测。顺序不能反 |
| P0-3 | 三分类判据不稳定 | 同一份输入连跑两次，一次判 B 一次判 C，给用户的行动指令是相反的 | 改法明确（把描述性判据换成硬阈值，如"核心要求命中不足 1/3 判 C"），但要重跑整套回归验证，属于下一版工作量 |
| P1 | 无埋点、无账号、无全局限流 | 成本与使用情况只能靠感觉 | 都依赖"有真实用户"这个前提 |
| P1 | 模型单点依赖 | 主用模型挂了会退到备选，备选也挂就报错 | 已有 3 级回退，够用 |

**P0-3 是封版前最需要说清的一条**：页面上的分类结论目前只能当参考意见，不能当判决。这句话我在页面上也写了，没有藏。

## 五、成本

- 一次完整诊断 = 三次模型调用 ≈ 5000 tokens，约 1 分钱。
- 平台侧成本 = 0（用户自带 Key 模式）或所有者额度（免 Key 模式）。
- 贵的不是模型，是事实库要人工建。这一条决定了它不能被做成"一键上传即出结果"。

## 六、如果继续做，按这个顺序

1. **找 3 个正在投简历的人，各跑一次，只问一句：「哪一句是你原本没想到的？」**
   - 两人说得出来 → P0-1 关掉，产品定位成立。
   - 多数说不出来 → 产品要重做，方向从"改简历"转向"投递决策"。
2. **把三分类判据换成硬阈值**，用现有的 5 份样本 + 真实简历做回归，要求同一输入两次分类一致。
3. **加投后回报入口**（投了几家 / 有没有面试 / 面了问什么），才开始有反馈回路。

三步必须按顺序，第 2、3 步在没做第 1 步之前做，都是在给没人用的东西加功能。

## 七、什么情况下解冻

只在这三种情况下重新打开这个项目：

- 有真实用户反馈了具体的一句"我原来没想到"，需要据此改提示词；
- 三分类被判据不一致坑到了具体的人（不是理论上的不一致）；
- 要把它作为面试作品讲，需要按对方岗位方向补一节针对性材料。

否则不动。**一个能跑的产品停在 v0.5，比一个永远在改的 v0.x 更能说明问题。**
