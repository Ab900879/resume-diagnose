# 产品手记 · 这个东西是怎么做出来的

> 写给想看过程的人。这里面没有成功学，只有三个被我否掉的省事方案、两个上线前抓到的 bug、一笔成本账，和一条我没让 AI 碰的线。
>
> 结论先说：**这个产品目前没有真实用户，只有作者本人。** 这句话在 README 和 PRD 里都写着，这里解释为什么明知是短板还敢写。

## 一、起点：一个被数据推翻的假设

项目最初的想法就是"简历优化助手"——帮人把简历改得更好看。

第一版提示词（v0.1）拿 5 份样本测完，假设被推翻了：

> 5 份里有 4 份，工具给了它们不该拿的改写建议。
> 其中 3 份根本没有岗位要的核心能力，工具还在帮它们润色"配合完成 20 场活动"。

那一刻的判断：**对能力不够的人，润色是害人**——等于把他推进面试然后被挂。所以流程倒过来了：先判该不该投（A/B/C 三分类），判完 A 类才给逐句改写，C 类一句都不改。

这个转折不是设计出来的，是第一轮实测数据逼出来的。

## 二、三个被我否掉的省事方案

完整版在 [DECISIONS.md](DECISIONS.md)，这里说为什么否。

**D-002：不写爬虫。** 让工具自动抓 JD、抓简历格式，技术上能做。否掉的理由不是难，是《个人信息保护法》和平台协议。"能不能做"和"该不该做"是两个问题，AI 会帮你写爬虫，但法律风险它不承担。改成用户自己粘贴。

**D-003：不在提示词里写"禁止编造"。** 最省事的做法是加一句"请不要虚构"，一行字。没用——那是请求，模型可以不听，更关键的是**我没法验证它听没听**。改成结构强制：每条经历拆成带编号的事实条目，输出每句话必须挂编号，交付前跑校验器。代价是每份简历要先人工建事实库，"一键上传"没了。我认这个代价，因为这个产品的卖点就是不留一句没出处的话。

**D-005：不先做网页。** "三天给你一个网页"很容易，但空洞不是因为缺代码，是因为没人用过。所以先做 7 天人力版流程，把环节跑通再写代码。

## 三、上线前抓到的两个 bug（都来自真实端到端测试）

**事实拆分粒度错了。** 第一次用真实 API 跑通全流程时发现：一条经历被拆成了两条事实条目，导致"动词升级"校验完全失效——因为校验器对照的原文已经不在同一个条目里了。修复方式：拆分提示词里加了"一条经历 = 一个可独立验证的动作单元，不要按句子拆"。

**校验器误报。** 一份简历原文里本来就写着"负责场地对接"，校验器把"负责"当成把"协助"升级成了"负责"，拦下了正确的句子。**防编造的机制自己制造了误伤**——这比漏报更危险，因为用户会因此不信任工具。修复：先查原文里是否本来就含这个动词，含就放行；修完用新旧两版各跑一遍回归，确认误报消失、真错误还抓得住。

这两个 bug 都不是代码 review 看出来的，是把真实 API 调通、拿真实数据跑出来的。**这也是我做端到端测试而不是只做单元测试的原因。**

## 四、两个产品决策，都来自"HR 会不会关掉页面"

**必须有不填 Key 的入口。** 第一版上线后我自己打开看了一眼：第一屏就要求填 API Key。我自己是开发者都犹豫，HR 会在这一步直接关掉。所以加了一个"打开一份跑好的报告"演示入口，用一次真实诊断的输出做内置数据——HR 不填任何东西就能看到完整报告长什么样。

**架构由一次跨域测试决定。** 做网页版之前先测了"浏览器能不能直接调模型 API"：DeepSeek 允许跨域调用，智谱不允许。就这一个测试结果定了整个架构：纯静态站 + 用户自带 Key + 数据只存浏览器 localStorage。**简历不出这台设备**——这不是功能，是合规底线，也省掉了服务器。

## 五、成本账（被问就答这三个数）

- 一次完整诊断 = 两次调用（建事实库 + 诊断）≈ **3300 tokens**
- deepseek-chat 约 2 元/百万 tokens → 一次约 **0.007 元**
- 用户自带 Key → **平台成本 0**

就算日活一千，模型费也不到十块钱。这个产品贵的不是模型调用，是事实库要人工建。

## 六、我怎么用 AI，哪条线我没让它碰

页面代码是 AI 生成的，一个下午。但有三类决定 AI 给不了：

| 类别 | 例子 | 为什么 AI 给不了 |
|---|---|---|
| 该不该存在 | C 类不给改写，会流失用户 | 流失的代价只有产品负责人承担 |
| 什么叫做对了 | "哪一句是你原本没想到的" | AI 会认为格式完整就是好 |
| 用户的原话 | "我其实只是搬桌子" | AI 只能生成看起来很真实的话 |

一句话的分界线：**错了要有人负责的，我自己来；错了可以重来的，交给 AI。**

## 七、现在缺什么（也是下一步）

1. **真实用户。** 目标动作：找 3 个正在投简历的同学，只问一句"你上次改简历最纠结的是哪一句"。P1 假设写在 PRD 里。
2. **C 类占比。** 如果真实人群里 C 类超过一半，产品定位要从"改简历"转向"投递决策"（判据见 D-006）。这个数只有真人能给。
3. **C 类输出的升级。** 现在只判"先攒经历"，下一步要给出"怎么攒"——用户自己反馈的：C 类用户需要的不是判死刑，是接下来三个月干什么能变成 B 类。
